이 파일은 Partner Center에 업로드할 원본입니다. 로컬 설치용 서명본은 별도 폴더에 보관했습니다.

현재 PC에는 테스트 앱과 인증서 등록이 남아 있습니다.
제거를 시도했지만 관리자 확인 창이 취소되어 완료되지 않았습니다. 서명용 개인 키는 삭제됐습니다. WACK 검사 후 정리 명령을 실행하면 테스트 앱과 이번에 등록한 인증서 신뢰를 제거할 수 있습니다.

1. 지금까지 진행한 작업

기존에 준비되어 있던 앱

C# / WPF / .NET 8 기반 Windows 파일명 일괄 변경 도구입니다. 찾아 바꾸기, 템플릿, 영문 대소문자, 순번 모드와 미리보기·이름 충돌 검사·되돌리기·일반/다크 모드가 있었습니다. 저장소에는 자체 포함 단일 EXE도 있었습니다.

이번 MSIX 작업에서 추가한 내용

  1. 저장소와 기존 Store 안내를 확인하고 패키징 설정이 없는 상태를 확인했습니다.
  2. 제공받은 Partner Center 화면의 패키지 이름·게시자·게시자 표시 이름을 반영했습니다.
  3. MSBuild 패키징 프로젝트, 매니페스트, 빌드 스크립트와 Windows SDK 도구 복원 설정을 추가했습니다.
  4. 기존 app.ico로부터 패키지 PNG 로고 3종을 만들었습니다.
  5. 자체 포함 Release 배포 후 MakeAppx로 x64 MSIX와 SHA256 확인 파일을 만들었습니다.
  6. 기존 Core 테스트 125개, 패키지 구성·아이콘·런타임·해시 검증을 통과했습니다.
  7. 7일짜리 테스트 인증서로 복사본에 서명하고, 개인 키는 즉시 삭제했습니다.
  8. 승인받은 관리자 절차로 테스트 인증서를 등록하고 MSIX를 실제 설치했습니다.
  9. 설치된 패키지를 실행하여 파일명 변경·되돌리기·대소문자 변경·충돌 차단·설정 보존을 확인했습니다.
  10. 설치·제거·WACK 재현 스크립트와 안내를 작성하고 공식 인증 키트 설치 파일을 준비했습니다.

이번 패키징 변경은 아직 Git 커밋하지 않았습니다. 소스 백업은 현재 작업 파일의 스냅샷이며 Git 이력을 포함하지 않습니다.

5. 이제 무엇을 하면 되는가

다음 순서는 WACK 검사 → 패키지 업로드 → 소개 정보 작성 → 심사 요청입니다.패키지 업로드와 소개 작성은 초안 상태로 먼저 준비할 수 있습니다. 최종 심사 요청 전에는 남은 검사를 마치세요.

  1. Windows App Certification Kit 설치·검사06_WACK설치도구/winsdksetup.exe에서 Windows App Certification Kit 구성 요소를 설치합니다. 관리자 PowerShell로 원래 작업 폴더의 packaging/Test-Wack.ps1을 실행하고 XML/HTML 보고서의 실패·미실행 항목을 확인합니다. 현재 앱은 이미 설치되어 있습니다.
  2. Partner Center에서 제출 초안 시작Partner Center에서 File Renamer_Dohi → 제출 시작 → 패키지로 이동합니다. 02_스토어제출용/Dohi.FileRenamerDohi_1.0.0.0_x64.msix를 올리고 검증 결과를 확인합니다. 확장자를 .msixupload로 바꾸지 않습니다.
  3. 스토어 소개와 배포 설정 작성한국어 설명, 실제 화면 캡처, 카테고리, 가격·국가, 연령 등급, 게시 시점 및 계정/앱에 필요한 지원·개인정보 관련 항목을 작성합니다. 지원 연락처와 공개 URL 등은 아직 이 작업에서 확정하지 않았습니다.
  4. 최종 확인 후 심사 요청패키지 오류와 제출 화면의 미완료 항목을 해결하고 게시 설정을 확인한 뒤 인증 심사를 요청합니다. 패키지 생성 성공이나 로컬 테스트 통과가 Store 승인 완료를 의미하지는 않습니다.
  5. 필요 없어진 테스트 설치 정리WACK까지 마친 후 아래 제거 명령을 원래 저장소에서 실행합니다. 현재 테스트 앱의 로컬 설정도 삭제되며, Store 제출용 MSIX 파일은 유지됩니다.

소개 문구 초안

여러 파일의 이름을 한 번에 정리하는 Windows 도구입니다. 찾아 바꾸기, 날짜 등을 조합하는 템플릿, 영문 대소문자 변환, 순번을 지원합니다. 변경 결과를 미리 확인하고 이름 충돌을 검사할 수 있으며, 마지막 실행을 되돌릴 수 있습니다.

runFullTrust 사용 목적 초안

사용자가 선택하거나 끌어다 놓은 로컬 파일의 이름을 일괄 변경하는 WPF 데스크톱 앱입니다. 파일 이름 변경, 충돌 검사 및 되돌리기를 위해 데스크톱 프로세스로 실행됩니다.

6. 재빌드와 검사 명령

일반 PowerShell에서 원래 작업 폴더로 이동해 실행합니다.

Set-Location -LiteralPath 'C:\Users\최경태\orca\file-renamer-tool'
dotnet test FileRenamer.sln -c Release
dotnet msbuild packaging/FileRenamer.Package.proj /t:Build

다음 버전 예시:

dotnet msbuild packaging/FileRenamer.Package.proj /t:Build /p:PackageVersion=1.0.1.0

인증 키트 설치 후 관리자 PowerShell에서 검사:

powershell -NoProfile -ExecutionPolicy Bypass -File packaging/Test-Wack.ps1

테스트가 끝나면 관리자 PowerShell에서 정리:

powershell -NoProfile -ExecutionPolicy Bypass -File packaging/Install-TestPackage.ps1 -Uninstall
