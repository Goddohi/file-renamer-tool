## Goal
사용자가 Windows 데스크톱 앱(C# WPF)에 파일들을 끌어다 놓고, **네 가지 모드 중 하나**(찾아 바꾸기 / 템플릿 / 대소문자 / 순번)를 골라 규칙을 입력하면, 모든 파일의 새 이름을 미리보기로 확인한 뒤 한 번에 적용하고, 필요하면 마지막 실행을 되돌릴 수 있게 한다.

## Constraints
- 플랫폼: Windows 데스크톱 GUI, **C# / WPF / .NET 8** (Round 8에서 확정)
- 배포: 설치 없이 실행되는 self-contained 단일 exe (`dotnet publish -p:PublishSingleFile=true`)
- **모드는 한 번에 하나만 적용** (규칙들을 이어서 적용하는 파이프라인은 없음)
- **확장자는 모든 모드에서 변경하지 않음**. 변환 대상은 마지막 `.` 앞의 이름 부분만
- 이름 변경은 파일이 있는 원래 폴더 안에서만 (이동하지 않음)
- 규칙 로직(이름 계산)은 UI와 분리된 순수 함수로 두어 단위 테스트가 가능해야 함
- Windows 파일명 금지 문자(`\ / : * ? " < > |`)가 결과에 생기면 충돌과 같은 방식으로 오류 표시

## Non-Goals
- 여러 규칙을 이어서 적용하는 파이프라인, 규칙 순서 편집
- 하위 폴더 재귀 처리 (폴더를 놓으면 바로 아래 파일만 추가), 폴더 자체 이름 변경
- 여러 단계 되돌리기 (마지막 1회 실행만 되돌림)
- 파일 날짜(수정일/생성일) 기반 `{날짜}`
- 여러 회사명/이름 프로필 저장
- 찾아 바꾸기 규칙 여러 줄 동시 적용
- 탐색기 우클릭 메뉴 통합

## Acceptance Criteria
**파일 선택 & 미리보기**
- [ ] 1. 탐색기에서 파일(또는 폴더: 바로 아래 파일만 추가, 하위 폴더 무시, 중복 경로는 한 번만)을 창에 끌어다 놓거나 "파일 추가" 버튼(OpenFileDialog, 다중 선택)으로 목록에 추가할 수 있다. 목록에서 개별 삭제 / 전체 비우기가 가능하다.
- [ ] 2. 목록은 `현재 이름 | 새 이름` 열을 보여주며, 모드나 입력값이 바뀌면 즉시 갱신된다.
- [ ] 3. 새 이름이 (a) 목록 안의 다른 결과와 같거나, (b) 같은 폴더의 기존 파일(목록에 없는 파일)과 같거나, (c) 금지 문자를 포함하거나 비어 있으면 해당 행을 빨간색으로 표시하고 **적용 버튼을 비활성화**한다. 대소문자만 다른 이름도 충돌로 본다 (Windows는 대소문자를 구분하지 않음).
- [ ] 4. 이름이 바뀌지 않는 파일은 건너뛴다 (충돌로 보지 않음).

**찾아 바꾸기**
- [ ] 5. `찾을 글자` + `바꿀 글자` 입력. 바꿀 글자가 비어 있으면 삭제. 예: `보고서(최종)` 에서 `(최종)` → `` ⇒ `보고서`.
- [ ] 6. 기본은 일반 문자열 검색(모든 위치 치환). "정규식 사용" 체크 시 .NET Regex로 동작한다. 예: `\d+` → `` 로 숫자 제거.
- [ ] 7. 잘못된 정규식은 앱이 멈추지 않고 입력칸 아래에 오류 메시지를 표시하며 적용 버튼을 비활성화한다.

**템플릿**
- [ ] 8. 변수: `{날짜}` = 오늘 날짜(설정의 형식, 기본 `yyyyMMdd`), `{회사명}`, `{이름}` = 설정값, `{파일명}` = 원래 이름(확장자 제외). 중괄호 밖 글자는 그대로 둔다. 예: `{날짜}_{회사명}_{파일명}_{이름}` + `견적서.xlsx` ⇒ `20261022_오르카_견적서_최경태.xlsx`.
- [ ] 9. 알 수 없는 변수(`{abc}`)는 오류로 표시한다. 마지막에 쓴 템플릿은 다음 실행 때 복원된다.

**대소문자**
- [ ] 10. 4가지 옵션: 전체 소문자 / 전체 대문자 / 첫 글자만 대문자(나머지는 소문자) / 단어마다 첫 글자 대문자(단어 구분: 공백, `_`, `-`). 한글 등 대소문자가 없는 글자는 그대로 둔다. 예: `my REPORT_final.PDF` → 첫 글자만 ⇒ `My report_final.PDF`.

**순번 (전체 재설정)**
- [ ] 11. 입력: 기본 이름, 시작 번호(기본 1), 자릿수(기본 1 = 0 채우기 없음, 예: 3 ⇒ `001`), 구분자(공백 / `_` / `-` / 없음, 기본 공백). 예: `보고서`, 시작 1, 자릿수 3, `_` ⇒ `보고서_001.pdf, 보고서_002.jpg…` (각자 확장자 유지).
- [ ] 12. 번호는 목록에 보이는 순서대로 매긴다. 목록 행을 드래그하거나 위/아래 버튼으로 순서를 바꿀 수 있다.

**적용 / 안전장치**
- [ ] 13. 적용 시 각 파일을 `File.Move`로 이름 변경한다. 목록 안 파일끼리 이름을 맞바꾸는 경우(A→B, B→A)도 임시 이름을 거쳐 정상 처리한다.
- [ ] 14. 일부 파일이 실패하면(사용 중, 권한 없음, 파일 없음) 나머지는 계속 처리하고, 끝난 뒤 실패 목록(파일명 + 사유)을 대화상자로 보여준다.
- [ ] 15. "되돌리기" 버튼은 마지막 실행에서 성공한 변경을 원래 이름으로 되돌린다. 되돌리기도 실패 목록을 보여준다. 되돌릴 것이 없으면 비활성화한다.
- [ ] 16. 적용 후 목록은 새 이름(현재 상태)으로 갱신된다.

**설정**
- [ ] 17. 설정 화면에서 날짜 형식(.NET 형식 문자열, 미리보기 표시), 회사명, 이름을 편집한다. 설정과 마지막 템플릿/모드 입력값은 `%AppData%\FileRenamer\settings.json`에 저장되고 재실행 시 복원된다.

**품질**
- [ ] 18. 이름 계산 로직(4개 모드 + 충돌 감지)에 대한 단위 테스트(xUnit)가 있고 모두 통과한다. 위 예시들이 테스트 케이스로 들어간다.
